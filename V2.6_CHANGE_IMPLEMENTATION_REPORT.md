## Preserved V2.5 Principles

- KISS, YAGNI, 80/20.
- High Cohesion, Low Coupling, Modular, Adaptable.
- Stable Core / Flexible Edge.
- Runtime Page Inventory as publication SSOT.
- Human approval gates.
- Representative + risk-based QA.
- Evidence discipline and no fabricated facts.
- Competitive Coverage, Minimum Wiki Coverage, Navigation Coverage, and Partial Page rules.
- Intentional no-media remains valid when positively justified.
- Explicit deployment authorization, Git/release boundaries, domain/DNS hard gates, and final production verification.

## Deliberate Non-Changes

- Did not add image quotas, mandatory galleries, automatic visual scoring, automatic media scraping, Press Kit downloading, copyright/licensing engine, media DAM, CMS, database, page builder, visual DSL, media DSL, transport engine, or reviewer orchestration engine.
- Did not move media lifecycle fields into Runtime Page Inventory.
- Did not prescribe exact Starter audit code or component implementation.
- Did not turn third-party media fallback into a universal iframe abstraction.
- Did not commit, push, tag, create a release, open a PR, or write to the V2.5 or V2.6 remotes.

## Possible Ambiguities

- `PROJECT_BRIEF.md` is the preferred home for Official Visual Evidence, but the SOP allows another existing planning authority when a real project already has one.
- Human waiver language is intentionally methodology-level; a future Master Prompt can define the exact execution phrasing.
- Package D remains light in GAME_SOP by design; detailed validation code belongs to GAME_SITE_STARTER.

## Recommended Regression Checks

- Bomb Farm: confirm technical visual PASS cannot ship while real game recognition remains weak.
- Afterworld pre-recovery: confirm missing key art, sparse guide imagery, and publisher-web-derived palette lead to `REVISE` or `BLOCK`.
- Afterworld recovered: confirm official key art, semantically matched guide images, real-game palette, and intentional YouTube fallback are approvable.
- Evidence transport: simulate preferred Git/API reader failure and confirm approved read-only fallback can verify provenance without false project blocker.
- Official source reader: simulate preferred reader auth/transport failure and confirm approved read-only official-source fallback preserves provenance.
- C2C capability: confirm reviewer evidence-access limits produce `REVIEWER CAPABILITY BLOCKED`, not `PROJECT BLOCKED`.
- Logo/chrome: confirm semantic and decorative logos remain allowed and do not satisfy or fail page-content media requirements.
