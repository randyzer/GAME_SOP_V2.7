# P0 / P1 / P2 Roadmap — v2.6

## Important Principle

P0/P1/P2 describes **evidence/readiness depth**, not simply whether an entire page may exist.

Separate:

```text
Page existence
Claim completeness
Database completeness
Meta/recommendation readiness
```

## P0 — Launch-Useful Coverage

Criteria:

- enough reliable public facts to answer a real player intent;
- no unsupported claims;
- strong player/structural/competitive value.

A P0 page may intentionally be partial if its limits are clear.

|---|---|---|---|---|---|
|  |  |  |  |  |  |

## P1 — Data Collection / Deep Reference

Criteria:

- screenshots/UI transcription required;
- entity-level data incomplete;
- deeper extraction/observation required;
- database completeness not ready.

A P1 dependency does **not** automatically suppress a useful overview page.

| Page / Expansion | URL | Required Data | Source | Can Partial Page Publish Earlier? | Status |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

## P2 — Meta / Community Evidence

Criteria:

- best/tier/meta;
- repeated testing;
- community consensus;
- patch stability;
- recommendation methodology.

| Page / Feature | URL | Evidence Needed | Status |
|---|---|---|---|
|  |  |  |  |

## Example

```text
Skill Tree Overview Guide = P0/P1 partial
Exact Skill Tree Node Database = P1
Best Skill Tree Build = P2
```

## Rule

Do not fabricate P2 content.

Do not use “incomplete detailed data” as the only reason to suppress a high-value page when a verified partial page can satisfy the intent.

Every public P0 route must still receive a media lifecycle row in `MEDIA_DECISION_TABLE.md`. P0 status does not require media quota fulfillment, but high-priority media gaps, no-media exceptions, and rights/risk decisions must be visible before Human Planning Gate.
